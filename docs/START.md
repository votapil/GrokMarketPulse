| # | Что | Зачем |
|---|---|---|
| 1 | `PLAN.md` §0–§3 | стек, демо-сценарий, что не делаем, замороженные контракты |
| 2 | `PLAN.md` §4 своя дорожка, §5 карточки первых 3–4 своих задач | что делать сегодня |
| 3 | `PLAN.md` §6, §7, §11 | git-протокол, приёмка, правила работы с фичами — дословно |
| 4 | `docs/STACK.md` — только свои разделы | A: x.ai + Convex · B: Wonder, Firecrawl, Exa, Render, Convex (actions, деплой) |
| 5 | `AGENTS.md` | 30 секунд |

Дорожка B дополнительно: `PLAN.md` §10 целиком до первого промпта. Пункты 10.2 (1–3) делаются руками:
clone, ключи личным сообщением, приглашение в Convex-команду (это делает A). Для `T-03` Convex не нужен — только Wonder OAuth.

## Цикл сессии (обе машины)

```
/resume-session → git pull --rebase → задача по карточке → verification-loop → /checkpoint create T-NN
→ commit "T-NN: …" → pull --rebase → push → /save-session
```
Подробно — `PLAN.md` §11.0.

## Промпты

### Дорожка A, первая сессия

```
Прочитай PLAN.md целиком, AGENTS.md и docs/STACK.md (разделы Convex и x.ai).
Я — дорожка A. План утверждён, брейнсторм не нужен — сразу к карточкам.
Работаем строго по PLAN.md: одна задача = один коммит, только файлы из «Владеет»,
галочка в §4 тем же коммитом, git-протокол §6 дословно, цикл сессии §11.0.
Начни с T-01. Перед кодом — карточка и её «Готово, когда». В конце запусти команду
из строки «Проверка», покажи вывод, /checkpoint create T-01, и только потом коммит и push.
После T-01 — T-02. Перед T-12 остановись, /save-session, и спроси меня.
```

### Дорожка B, первая сессия

```
Прочитай PLAN.md целиком (особенно §10 и §11), AGENTS.md и docs/STACK.md
(разделы Wonder, Firecrawl, Exa, Render, Convex).
Я — дорожка B. Напарник прямо сейчас делает T-01 и T-02 и запушит их в main.
План утверждён, брейнсторм не нужен — сразу к карточкам.
Работаем строго по PLAN.md: одна задача = один коммит, только файлы из «Владеет»,
галочка в §4 тем же коммитом, git-протокол §6 дословно, цикл сессии §11.0.
Файлы дорожки A не трогаем никогда.
Сначала пройди чек-лист §10.5 (кроме пунктов, которым нужны T-01/T-02) и скажи,
чего не хватает. Потом T-03: Wonder MCP по карточке, первый вызов —
get_design_context без pageId. Коммитить только docs/DESIGN.md.
Когда в main появится T-02 — git pull --rebase и T-05.
```

### Каждая следующая задача (обе машины, подставить номер)

```
/resume-session, затем git pull --rebase origin main. Открой PLAN.md, карточку T-NN.
Проверь, что её зависимости отмечены [x]; если чужая ещё не пришла — работай против фикстур.
Поставь [~] в §4 и запушь эту строку. Скиллы и MCP из строки «Скиллы/MCP» —
до первой строки кода. Только файлы из «Владеет».
В конце: скилл verification-loop, команда из «Проверка» с выводом, три состояния
на экране, npm run build, галочка [x], /checkpoint create T-NN, коммит "T-NN: …",
git pull --rebase, push. Если сессия заканчивается — /save-session.
```

### Приёмка после чужого push (обе машины)

```
git pull --rebase origin main, git log --oneline -5. Прогони §7 по последнему
чужому коммиту: /code-review (+ /react-review, если есть .tsx), npm run build,
пройти демо-сценарий §1 целиком. Отметь рубрику да/нет. Строку «T-NN принято»
или «T-NN возврат: …» — в §7 «Журнал приёмки», запушить.
```

### Если что-то сломалось

```
Не чини наугад. Скилл systematic-debugging: воспроизведи, найди причину, потом правь.
Красный build — /build-fix (или /react-build для JSX). Если сломан файл чужой дорожки —
не правь, напиши напарнику: «T-NN возврат: …» в §7.
```
